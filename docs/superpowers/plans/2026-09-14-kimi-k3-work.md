# BloxCode Work Kimi K3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Vercel-hosted Work-style coding agent powered by self-hosted Kimi K3/vLLM to the existing BloxCode repository without breaking its CLI.

**Architecture:** Next.js route handlers orchestrate Kimi K3 through a small OpenAI-compatible vLLM client and execute tools only in persistent Vercel Sandbox workspaces. The browser renders chat, tool trace, terminal, files, and diff while sharing one workspace ID across all routes.

**Tech Stack:** Next.js 16+, React 19+, Node.js 22+, `@vercel/sandbox`, native Fetch, Node test runner.

**Spec:** `docs/superpowers/specs/2026-09-14-kimi-k3-work-design.md`

## Global Constraints

- Do not modify existing CLI code under `bin/` or `src/`, and keep the root `package.json` unchanged.
- Kimi K3 is reached only through an OpenAI-compatible vLLM endpoint.
- Preserve complete Kimi assistant messages across tool turns.
- Never execute agent shell commands on the Vercel function host.
- All workspace paths remain under `/home/vercel-sandbox/workspace`.
- Maximum agent tool iterations defaults to 12.
